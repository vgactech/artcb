## Pourquoi les URL Replit en dur cassaient tes tests multi-comptes

Avant, le protocole contenait des noms du style `artcb--vgacofficiel.replit.app` et `artcb--vgac42371.replit.app`.

Conséquence : un **autre** compte Replit (ou un clone sur un VPS) n’était **pas** dans le carnet. Git ne peut pas connaître le hostname que Replit attribuera **demain** à Alice, Bob ou à toi sur un 3ᵉ compte.

**Après (ce commit) :** git ne connaît que les **4 IP**. Replit injecte tout seul `REPLIT_DEV_DOMAIN` (ou `REPLIT_DOMAINS`, ou `REPL_SLUG` + `REPL_OWNER`). Au démarrage le clone :

1. lit le carnet des 4 IP ;
2. calcule **sa** URL ;
3. appelle « me voici » sur les 4 seeds.

Un 5ᵉ serveur OVH : mettre `ARTCB_NODE_PUBLIC_URL=http://SON_IP:8000` (IP publique autorisée). Un nom de domaine à soi : `ARTCB_PUBLIC_PEER_HOSTS=mondomaine.example` sur les seeds (pour ne pas laisser n’importe qui enregistrer `evil.example.com`).

**Pour que tes Replit actuels voient le nouveau code :** republier / redémarrer Autoscale **après** ce SHA. Tant qu’ils restent sur `99e83b` / `174-devnet-1`, ils répondent 503 sur l’annuaire (ancien code). Ce n’est pas un hostname à coller dans git : c’est **leur** snapshot qui est en retard.
